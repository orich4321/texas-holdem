# AI Poker Coach

## Activation — free-only operational boundary

The UI, durable jobs, statistics, privacy boundary and Gemini adapter are
implemented. Inference is **disabled by default**. No live Gemini integration
test is claimed without a real key.

1. In [Google AI Studio](https://aistudio.google.com/api-keys), create a key in a
   separate project with **Free** billing tier and **no linked Cloud billing
   account**. Do not enable billing or use the application's existing OAuth
   project if it has billing enabled. Restrict the key to the Gemini API.
2. In Vercel project `texas-holdem-play`, set these **server-only** production
   environment variables, then redeploy:

   ```text
   GEMINI_API_KEY=<secret key, never commit or paste into chat>
   GEMINI_COACH_MODEL=gemini-3.8-flash
   GEMINI_FREE_TIER_CONFIRMED=true
   AI_COACH_ENABLED=true
   CRON_SECRET=<independent random secret, if not already configured>
   ```

3. Verify the key's project remains Free in AI Studio. Use a finished test game
   with two separate authenticated accounts. Generate one report, leave the
   page, return, then open it from history and another device. Google usage
   should not rise when opening the completed report again. Test a second
   participant cannot read the first participant's report.

**Important:** Google's API has no request option that makes an API key from a
paid project "free only". The app's confirmation flag is a deployment guard,
not proof of billing status. The no-charge guarantee therefore depends on
keeping that key's project disconnected from billing. The app never enables
billing, never changes providers/models on failure, uses no paid Batch/grounding,
and refuses models outside its reviewed allowlist. Remove/disable the key if
the project's billing status changes. No Vercel/Supabase plan upgrade is needed
by this feature; their own resource quotas still apply.

avatars, tokens and authentication data are not included in model input. The
hero's own cards and game decisions are necessary input. Use the feature only
if that free-tier data policy is acceptable.

## Integration and authorization

- `CoachButton` is shared by the final summary, archive cards and replay page.
  `/coach/[joinId]` contains the same private report viewer for every entry.
- All `/auth/history/:joinId/coach` endpoints require the existing opaque
  account-session cookie. They derive the player from the database. Client
  player/account/model overrides are rejected, not trusted.
- Only finished, released, non-hidden games in the caller's archive qualify.
  Reports are inaccessible if the game's existing archive policy denies access.
  A host cannot read another player's report.
- `CoachReport` has a unique `(roomId, playerId)` key; creation uses PostgreSQL
  `ON CONFLICT DO NOTHING`. Completed reports cannot be regenerated by any API.
  Failed jobs reuse their original model/engine version and saved checkpoints.
  A pending checkpoint from another engine version is stopped for explicit
  administrative review rather than mixed with newly evaluated decisions.
- `CoachReport`, `CoachHand`, `CoachQuota` and `CoachPublicHand` have RLS enabled
  and no client Data API grants or policies. Only the existing trusted server
  database connection can access them. No service-role key is sent to browsers.

## Data flow and privacy

1. RoomRepository verifies signed historical snapshots using existing keys.
2. The existing `projectHandHistory` is the sole card visibility boundary:
   own cards, public showdown cards and each individually revealed card only.
3. The coach derives **before-action** snapshots: board at that time, actual
   position, blinds, stack, current bet, legal ability to raise, prior actions
   with street names, and actual incremental chips paid. No future board or
   result enters decision input. Blind scales are authenticated per snapshot.
4. A separate explicit model allowlist omits **all** opponent hole cards, even
   those publicly shown later. It also omits results and end-of-hand boards.
5. Structured model output must cover every requested hand/decision exactly
   once, reference only real IDs and use valid street/domain classifications.
   Invalid output is never shown/saved as a completed analysis. Output is plain
   text rendered by React, never injected HTML.
6. The final viewer can show already-public opponent cards as historical
   context, separately from decision evaluation. It never shows a hidden card.

Prompt instructions are additional guardrails, not the privacy boundary.
LLM strategic judgements can still be wrong: the product explicitly is not a
Solver and exposes assumptions/confidence. The server can validate structure,
coverage, references and deterministic statistics, not prove poker optimality
or the truth of every strategic sentence generated by an LLM.

## Durable work / free quotas

- Jobs atomically claim short leases with `FOR UPDATE SKIP LOCKED`. Fencing
  tokens reject a stale worker's writes. No DB transaction stays open while
  calling Gemini. Expired leases are recoverable after process termination.
- Each call covers up to 4 hands and 8 decisions. A long hand is split into
  durable decision chunks. Every dealt/not-dealt hand gets an explicit record;
  no "interesting hands only" sampling is used for hand analysis. A hand with
  no player choice receives an explicit factual short explanation without AI.
- Each validated chunk is saved. Retries load only unfinished work. Final
  synthesis receives exact full-game statistical aggregates/rating counts plus
  bounded representative good/bad decisions. This bounds tokens for hundreds
  of hands; **all** hand analyses remain in the saved interactive report.
- Persistent project-wide gate: at most 1 call/12s, 500 calls/UTC day and 10,000
  calls/month. These are app safety caps, **not Google's promised allowances**.
  Google can impose lower limits. `429` pauses the shared gate and exponentially
  backs off; no paid fallback. Other transient/invalid outputs get up to 4
  automatic attempts, then require explicit resume with a cooldown.
- Vercel `waitUntil` continues independently of the tab. Each invocation is
  bounded, then authenticated self-continuations drain ready work. Configure a
  >=240s function duration (current Fluid default 300s) for the 180s window.
  The daily Hobby-compatible cron at 02:10 UTC recovers long cooldowns/failed
  continuation delivery; visits to an in-progress report also wake the queue.
  Therefore a closed browser + a long quota wait can delay resumption until
  the daily cron. This is not an always-on paid worker.
- On a persistent local server, a 30-second unref'd timer resumes due work.
- API completion cannot be transactionally committed together with Google's
  external inference: a crash **after** Google responds but **before** saving
  the checkpoint may repeat that uncommitted call. Already committed chunks
  and completed reports are never re-analyzed. Do not claim exactly-once
  external inference across that unavoidable distributed-system boundary.

Free capacity for 48 large reports/month cannot be guaranteed. Report latency
depends on the project's live limits and hand/decision count. Pending progress
is retained even if a daily/monthly allowance is exhausted.

## Statistics and scores

All percentages, opportunities, means, P&L, BB/100 and grades are calculated in
code. Every metric includes Hebrew definition, numerator, denominator and
sample reliability. No-opportunity metrics return null/N/A, never invented zero.
Preflop metrics are per actual hand opportunity; forced blind all-ins are not
voluntary choices. Postflop opportunity definitions are in `statistics.ts` and
included with the report. No ante/straddle support is assumed when not recorded.

Poker hand P&L includes side-pot awards and uncalled returns, but not external
jackpot fees/payouts/rebuys. Final account P&L is independently taken from final
stack minus all recorded buy-ins. BB/100 normalizes each hand by its real blind,
not the room's last configured blind. Changed player counts use per-hand seats.
Incomplete legacy action frames are flagged and excluded from dependent metrics.
Wins mean any share of a pot (including split/side pots); negative-profit hands
are counted separately, since winning a side pot can still leave net loss.

Rubric v1: excellent=100, good=90, reasonable=80, borderline=65, small mistake=50,
major=25, severe=0. Medium-confidence evaluations weigh 0.6, high weigh 1; low
confidence and uncertain decisions are excluded. Require 5 eligible decisions
for overall score and 3/domain; otherwise N/A. Overall score is the direct
weighted mean of decisions, not an average that double-counts domains. Financial
outcome does not influence it. Completed versions are immutable; a future
administrative algorithm migration must be explicit and separately reviewed.

## Egress and verification

Visible report pages poll compact metadata every 15–60 seconds; hidden pages
make no poll requests. Completed reports are fetched once and stop polling.
Archive lists select status/score only, never the report JSON. There are no new
queries/pollers on the gameplay hot path.

`CoachPublicHand` caches only explicitly rebuilt public geometry/actions from
verified snapshots, with **no hole cards, deck, avatar or private payload**. Six
reports share that public work instead of transferring six full snapshot
archives over the Supabase pooler. Per-player cards still pass through the
existing account-safe projector. Remaining egress is proportional to the
game history on first analysis and the size of each private saved report.

```sh
pnpm test
pnpm typecheck
pnpm lint
pnpm e2e
# Full tests with TEST_DATABASE_URL against a disposable PostgreSQL test DB:
NODE_ENV=test pnpm exec tsx --conditions=development --test --test-concurrency=1 tests/*.test.mjs
```

`tests/coach.test.mjs`: statistical denominators, visibility, no hindsight,
public-cache allowlist, output/rubric/configuration validation and HTTP isolation.
`tests/coach-ui.test.mjs`: real React rendering of button states and accessible
loading, route consistency, all-hand/street/position/confidence/error filters,
severity sorting and immutability of the saved report data.
`tests/server-coach.integration.test.mjs`: real signed history, partial reveals,
cross-account cache reuse, 10 concurrent requests, stale worker fencing,
immutable reports after restart/model change, persisted partial chunks, 429
recovery, global quota races, RLS and archive access revocation.

NEXT_PUBLIC_SERVER_URL=http://localhost:3101 pnpm --filter @texas-holdem/web exec next dev -p 3100

report. It must never be enabled in production.
